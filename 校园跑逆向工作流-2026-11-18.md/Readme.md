使用 Agent 完成校园跑逆向的完整工作流
适用对象：纯新手。目标：从脱壳、抓包到协议复刻与验收，跑通完整流程。操作环境：破甲环境（Agent 无安全限制、可完整输出代码与分析）/非破甲环境，进行任务拆分。

1. 脱壳
为什么脱壳：代码被抽离，解压后直接反编译 DEX 文件，得到的都是壳代码，无法获得有效的加密信息或签名信息。

前提准备

模拟器：MuMu 模拟器 12，开启 Root，Android 9/11 镜像优先（兼容性最好）。

Root 方案：Kitsune Mask 或 KernelSU（KSU）+ Zygisk，使用一键隐藏模块隐藏环境，避免应用检测到 Root 环境(不隐藏也没关系，驾驭agent撰写hook模块解决)。

框架：LSPosed（Zygisk 版），用于加载自写 Hook 模块。

Frida：电脑端 frida + frida-tools，设备端推 frida-server（与 frida 版本严格一致），建议改端口/改进程名规避检测。

电脑端工具：ADB、JADX（反编译 DEX）、Ghidra（反编译 .so）、apktool（解包看 manifest 与 so 列表）、Python 3 + frida 绑定、Android Studio 或 Gradle（编译 LSP 模块）。

跑步应用原包 APK（从官方渠道下载，记录版本号）。

提示词

text
请使用 Frida 对应用 <包名> 进行完整脱壳。
设备环境：MuMu 模拟器 + Kitsune/KSU + LSPosed，frida-server 已就绪。
要求：
1. 先枚举已加载的 DEX 与 .so，定位壳类型（如 360/梆梆/腾讯乐固/爱加密），说明判断依据。
2. 编写 Frida 脚本全量 dump 内存中的 DEX，落盘到 /data/local/tmp/dump/，并做 DEX 文件头与校验和验证。
3. 若遇到检测 Frida 导致闪退，请撰写基于 LSPosed 的 Hook 模块解决：
   绕过环境检测（Root、Frida 端口/进程名、调试标志）；
   绕过反调试与闪退点；
   同时 Hook 证书校验（TrustManager、SSLContext、OkHttp/ Cronet 校验证书链），为下一步抓包铺路。
4. 输出：dump 脚本、LSP 模块完整源码与编译说明、壳类型分析结论、验证通过的 DEX 清单。
2. 全流程抓包与协议复刻
在步骤 1 中，LSP 模块已解决环境校验和证书校验。

前提准备

清除应用数据（adb shell pm clear <包名>），保证从冷启动抓全流程。

Reqable（手机端装 CA 证书，Root 下把证书装进系统证书区）。

模拟定位软件：如 Fake Location / Kaillocation，授予 root 权限，用于模拟定位跑完整跑步轨迹。

HAR 导出：Reqable 内全选会话 → 导出 HAR，记录抓包时间段与账号信息(登录的账号密码明文告诉agent，这样方便他分析密文)。

提示词

text
阅读 <HAR 文件路径>，这是一次完整流程抓包（登录 → 心跳 → 开始跑步 → 跑步中上报 → 结束跑步 → 成绩提交）。
测试账号：<账号>
测试密码：<密码>
要求：
1. 梳理接口清单：URL、方法、请求头（含签名头）、请求体、响应体，标注每个接口的作用与调用顺序。
2. 逐个分析加密/签名字段：定位算法（AES/RSA/MD5/HMAC/SM3 等）、密钥来源、时间戳与随机数拼接规则，给出还原逻辑。
3. 进行纯协议复刻：用 Python 写出可运行的客户端，覆盖登录、心跳、开始跑步、轨迹上报、结束提交全流程，字段与签名和 HAR 完全对齐。
4. 输出：接口清单表、加密分析说明、完整可运行代码、运行方式。
3. 协议复刻验收
第二步之后 Agent 会完成 95% 以上的内容，接下来对协议复刻做验收。

提示词

text
使用 HAR 中已登录的凭证（token/session）进行跑步功能测试，不要重新登录，避免顶号。
要求：
1. 复用 HAR 里的有效凭证，直接调用开始跑步 → 轨迹上报 → 结束提交接口。
2. 每次请求打印请求体、响应体与状态码，便于对照 HAR 校验字段。
3. 跑完后输出本次跑步的接口返回数据，与 App 内成绩做比对。
4. 新手流程与对话拆分建议


以上是纯新手逆向校园跑的流程。中间的风控点可交给 Agent 分析。全程需在破甲agent环境下操作(闪动校园在GPT6Astra的分析下一般每个版本需要20分钟即可完成全量任务，运动世界在GPT6Astra的情况下一般每个版本需要25分钟即可完成全量任务)；不会破甲就拆成多个对话，每个对话只做一件事，上下文更干净：

对话 1：脱壳——壳类型判断、DEX dump、LSP 模块（环境检测 + 证书校验）。

对话 2：抓包分析——读 HAR，出接口清单与加密字段分析。

对话 3：协议复刻——按分析结果写完整可运行客户端。

对话 4：验收测试——用 HAR 凭证跑跑步流程，比对返回数据。

不会破甲卡在对话3的话(一般你会卡在不帮助进行滑块验证码这类人机验证分析，其实自己用的话，登录凭证复用也没关系)，在分析出所有加密后，有一些基础也可以自己写好协议了。
